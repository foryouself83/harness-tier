# Microcopy

The words on controls, states and messages. A label the user misreads is a failed task even
when the layout is right.

| Id | Rule | Violation signal | Fix direction |
|----|------|------------------|---------------|
| M1 | Buttons say what happens | "OK", "Yes", "Submit", "Continue" where the outcome matters | Verb plus object: "Delete project", "Send invite" |
| M2 | Confirmations name the consequence | "Are you sure?" with Yes/No | State what will happen; label buttons with the actions |
| M3 | Errors: cause, then fix | Codes, blame ("You entered an invalid…"), or no next step | What happened and what to do, in plain words |
| M4 | Empty states lead somewhere | A blank area or "No data" | Why it is empty and the action that fills it |
| M5 | One term per thing | "Workspace", "project" and "space" for the same object | One term, used everywhere |
| M6 | Front-load key words | Long labels where the distinguishing word comes last | Distinguishing word first |
| M7 | Links say where they go | "Click here", "Learn more" repeated | Link text naming the destination |
| M8 | Success is stated | An action completes silently | A short confirmation of what changed |
| M9 | No jargon | Internal names, technical states ("pending sync", "null") | The user's vocabulary |
| M10 | Sentence case, consistent tone | Mixed Title Case and sentence case; tone shifts between screens | One case convention and one voice |
