# Laws of UX

Psychology results that predict where a screen costs the user time or errors. Cite the law by
id in a finding's `heuristic` field when it explains the problem better than a heuristic does.

| Id | Law | What it predicts | Violation signal | Fix direction |
|----|-----|------------------|------------------|---------------|
| L1 | Fitts's Law | Time to hit a target grows with distance and shrinks with size | The primary action is small or far from where the user's attention ends | Larger, closer primary targets; keep related actions together |
| L2 | Hick's Law | Decision time grows with the number and complexity of choices | Long flat menus; many equal-weight buttons | Fewer visible choices; group, stage or recommend one |
| L3 | Jakob's Law | Users expect a site to work like the sites they already use | A familiar pattern placed or behaving unexpectedly (logo not linking home, cart elsewhere) | Follow the established pattern unless the gain is clear |
| L4 | Miller's Law / cognitive load | Working memory holds a small number of chunks | Long unchunked numbers or codes; many fields at once | Chunk, group, and split into steps |
| L5 | Doherty Threshold | Productivity drops when the system responds slower than about 400 ms | An action with no response or indicator inside that window | Optimistic UI or an immediate indicator |
| L6 | Tesler's Law | Some complexity cannot be removed, only moved | The user is made to do work the system could do (formatting, lookups) | Move the complexity into the system |
| L7 | Peak-End Rule | Experiences are judged by their peak and their end | A flow ending on an error, a dead end or a bare confirmation | A clear, positive end state with the next step |
| L8 | Von Restorff Effect | The item that differs is remembered | Everything emphasised, so nothing stands out | One emphasised element per region |
| L9 | Goal-Gradient Effect | Motivation rises near the goal | A multi-step flow shows no progress | Show steps and progress |
| L10 | Postel's Law | Be liberal in what you accept | Input rejected for spaces, dashes or case the system could normalise | Accept variants and normalise them |
